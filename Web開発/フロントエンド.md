# フロントエンド技術メモ

Web フロントエンドの汎用技術知識をまとめます。

---

## 1. Tailwind CSS の思想(utility-first)

### 何か

Tailwind は **CSS フレームワーク**ではなく **ユーティリティクラス集**です。

```html
<!-- 従来の CSS -->
<div class="card">...</div>
<style>.card { display: flex; padding: 1rem; background: #3b82f6; color: white; border-radius: 0.5rem; }</style>

<!-- Tailwind(utility-first) -->
<div class="flex p-4 bg-blue-500 text-white rounded-lg">...</div>
```

スタイルを HTML 内で完結させる思想です。

### メリット

- HTML/JSX とスタイルが同じ場所 → ファイル横断のスタイル探索が不要
- 不要な CSS が build 時に削除される(Purge)
- デザイントークン(色・余白・フォントサイズ)が一貫
- カスタマイズが柔軟(コンポーネントライブラリのスタイルを直接いじれる)

### デメリット

- HTML が長くなる(コンポーネント化すれば緩和)
- 学習曲線(クラス名を覚える必要)

## 2. UI コンポーネントライブラリの分類

UI 構築アプローチは大きく 3 種類:

| 方式                                  | メリット                                                | デメリット                                                          |
| ------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------- |
| **完成品型**(MUI / Chakra / Mantine) | コンポーネントが揃っている、即座に動く                  | スタイル固定的でカスタマイズが面倒、バンドル肥大、ロックイン       |
| **コピペ型**(shadcn/ui)             | 完成度の高い土台 + 完全カスタマイズ可能、ロックインなし | 初期セットアップに少し慣れが必要                                    |
| **自作型**(Tailwind 単体)           | 自由度最大、バンドル軽量                                | コンポーネント完成度ゼロ、全部作る必要あり                          |

「完成品型」と「自作型」の中間として **「コピペ型」** が現代の主流になりつつあります。

---

## 3. shadcn/ui の仕組みと採用理由

### 何か

**「コピペ式 UI ライブラリ」**。従来の npm パッケージとは違います。

- Radix UI(アクセシブルなヘッドレスコンポーネント)+ Tailwind CSS でスタイリング済みのコンポーネントを提供
- `npx shadcn-ui add button` で **ソースコードを自分のリポジトリにコピー** する(ライブラリではない)
- コピー後は完全に自分のコード → 自由に編集できる
- 依存パッケージが増えない、ロックインなし、必要な分だけ取り込む

### 仕組み

```bash
# 1. 初期化
npx shadcn-ui init

# 2. 必要なコンポーネントだけコピー
npx shadcn-ui add button
npx shadcn-ui add dialog

# 3. components/ui/ にソースコードがコピーされる
# 4. 自由に編集可能(Tailwind ベース)
```

### 採用される理由

- Vercel・Linear・Resend など多くのモダン B2B SaaS が採用、業界デファクト
- **Radix UI のアクセシビリティ**(WAI-ARIA、キーボード操作、フォーカス管理)が内蔵
- **完全な所有権**: コピー後はライブラリに依存しない、`npm update` で壊れない
- **学習コストゼロ**: コードは普通の React + Tailwind、特殊な構文がない

### デメリット

- アップデート追従が手動(コピーしたコードを各自更新する必要)
- 大量にコピーすると components/ui/ が肥大

---

## 4. ベストプラクティス: Tailwind + shadcn/ui の組み合わせ

### 推奨構成

```
apps/web/
├── components/
│   ├── ui/             # shadcn/ui からコピー(button, dialog, etc)
│   └── features/       # ドメイン固有コンポーネント
└── tailwind.config.ts  # デザイントークン定義
```

### 役割分担

- **shadcn/ui のコピー**: button, dialog, dropdown 等の汎用 UI(Radix のアクセシビリティを享受)
- **自作コンポーネント**: ドメイン固有の UI(プロジェクトカード、AI 生成 UI 等)
- **Tailwind**: 全コンポーネントのスタイリング

### バンドルサイズ

- shadcn/ui: 必要なコンポーネントだけコピーするので肥大しない
- Tailwind: build 時に未使用クラスが自動削除される(Purge)

---

## 5. 代替案との比較表

| ライブラリ        | 方式            | バンドル | カスタマイズ | アクセシビリティ |
| ----------------- | --------------- | -------- | ------------ | ---------------- |
| **shadcn/ui**     | コピペ型        | 軽量     | ◎(自由)    | ◎(Radix)       |
| Material UI (MUI) | 完成品型        | 重い     | △            | ○                |
| Chakra UI         | 完成品型        | 中       | ○            | ○                |
| Mantine           | 完成品型        | 中       | ○            | ○                |
| Tailwind 単体     | 自作型          | 軽量     | ◎            | ✗(自前)        |
| Headless UI       | コピペ型に近い  | 軽量     | ◎            | ○                |

B2B SaaS で独自性のある UI を作るなら **shadcn/ui + Tailwind** が現代の最有力解。
