# バージョン管理ツールメモ

Node.js のバージョン管理 / パッケージマネージャの選択肢と、`.mise.toml` / `.nvmrc` / `package.json#engines` の関係をまとめます。

---

## 1. Node.js バージョン管理ツールの選択肢

| ツール    | 言語サポート              | 速度        | 特徴                                                        |
| --------- | ------------------------- | ----------- | ----------------------------------------------------------- |
| **mise**  | Polyglot(Node/Python/Go/Ruby/etc) | ⚡⚡(Rust) | モダン、`.mise.toml` で全言語管理、env vars 管理機能も内蔵  |
| **fnm**   | Node のみ                 | ⚡⚡(Rust) | シンプル、`.nvmrc` 互換、最速クラス                         |
| **volta** | Node + パッケージマネージャ | ⚡(Rust)  | プロジェクト切替時に**自動で**バージョン切り替え(優秀な UX) |
| **nvm**   | Node のみ                 | 🐢(Bash)   | 最古参、最も広く使われる、起動が遅い                        |
| **asdf**  | Polyglot                  | 🐢(Bash)   | mise の前身的存在、設定が冗長                               |

### 用途別の選び方

| 状況                                       | おすすめ |
| ------------------------------------------ | -------- |
| 将来 Python / Go 等を触る可能性あり       | **mise** |
| Node 専用で軽量に済ませたい                | fnm      |
| `cd` するだけでバージョン自動切替が欲しい | volta    |
| 既に nvm を使っていて移行コストを払いたくない | nvm      |
| 大規模 OSS / asdf 利用中のプロジェクト     | asdf     |

新規セットアップなら **mise が現代の最有力** 選択。

---

## 2. mise の特徴

mise(旧 rtx)= Rust 製の polyglot バージョンマネージャ。

### できること

- Node / Python / Go / Ruby / Java / Terraform 等を**同じツール 1 つで管理**
- `.mise.toml` で全言語のバージョンを一元定義
- 環境変数管理(`[env]` セクションで定義可能)
- shim 方式で `cd` するだけで PATH が切り替わる
- `.nvmrc` `.tool-versions`(asdf 互換)も読める

### `.mise.toml` の例

```toml
[tools]
node = "22"
pnpm = "10"
python = "3.12"

[env]
NODE_ENV = "development"
DATABASE_URL = "postgresql://localhost:5432/dev"
```

### 基本コマンド

```bash
mise install           # .mise.toml に書かれたツールを全インストール
mise current           # 現在使われているバージョン表示
mise use node@22       # Node 22 を現在のディレクトリで使う(.mise.toml に追記)
mise upgrade           # ツール群を最新化
```

### shell 統合

`~/.bashrc` や `~/.zshrc` に以下を追加して有効化:

```bash
eval "$(mise activate bash)"  # or zsh / fish
```

## 3. パッケージマネージャ(npm vs yarn vs pnpm vs bun)

| ツール   | 速度    | ディスク効率                  | Workspaces | エコシステム |
| -------- | ------- | ----------------------------- | ---------- | ------------ |
| **pnpm** | ⚡⚡    | ◎(ハードリンク方式)         | ◎          | 安定・主流   |
| **bun**  | ⚡⚡⚡  | ○                             | ○          | 新興、注目株 |
| **yarn** | ⚡      | ○                             | ◎          | 安定         |
| **npm**  | 🐢      | △                             | ○          | 標準同梱     |

### pnpm を推奨する理由

- **ハードリンク方式**: 同じパッケージを複数プロジェクトで共有、ディスク効率最高
- **Strict 解決**: `package.json` に宣言されていない依存を import すると警告(隠れた依存防止)
- **Workspaces 標準サポート**: `pnpm-workspace.yaml` で柔軟に定義可能
- **catalog 機能**: 全 workspace のバージョン統一が可能(pnpm 9+)
- **Turborepo / Nx との相性◎**

### bun が選ばれない理由(2026 年時点)

- まだ新興、エッジケースで挙動が不安定
- ネイティブモジュール(Prisma 等)との互換性で問題が出ることがある
- 速度は最強だが、安定性で pnpm に軍配

ただし bun は急速に成熟中で、数年内に標準になる可能性あり。

## 4. `.mise.toml` / `.nvmrc` / `package.json#engines` の使い分け

### それぞれが読まれる場面

| ファイル              | 主な読み手                                           |
| --------------------- | ---------------------------------------------------- |
| `.mise.toml`          | mise(主に)                                         |
| `.nvmrc`              | nvm / fnm / volta / mise(互換)/ GitHub Actions   |
| `.tool-versions`      | asdf / mise(互換)                                  |
| `package.json#engines` | pnpm(`engine-strict=true` 時)/ Vercel / 多くのデプロイ先 |
| `package.json#packageManager` | corepack(Node 同梱)→ 自動で pnpm のバージョン切替   |

### Shipyard 等で推奨する 3 ファイル併用

```toml
# .mise.toml
[tools]
node = "22"
pnpm = "10"
```

```
# .nvmrc(mise を使わない人 / GitHub Actions 等のフォールバック)
22
```

```jsonc
// package.json
{
  "packageManager": "pnpm@10.14.0",
  "engines": {
    "node": ">=22.0.0",
    "pnpm": ">=10.0.0"
  }
}
```

### なぜ複数併用するか

- `.mise.toml`: 普段使う **メインの定義**(mise を使う人向け)
- `.nvmrc`: **フォールバック**(他のツールを使う人 / CI 向け)
- `package.json#engines`: **強制チェック**(誤った Node バージョンでインストールするとエラー / 警告)
- `packageManager`: **corepack 経由で pnpm を自動切替**(チーム全員が同じ pnpm バージョンを使う保証)

### 削れる場合

- 自分 1 人で開発、mise しか使わない: `.nvmrc` は削っても良い(`.mise.toml` のみで十分)
- ただし公開リポジトリにする予定 / Vercel デプロイで `engines` ではなく `.nvmrc` を使う等の理由があれば残す

## 5. corepack による packageManager 自動切替

### corepack とは

Node.js 16.10+ に同梱される **パッケージマネージャ管理ツール**。

`package.json#packageManager` に書かれたバージョンを自動でダウンロード・実行する仕組み。

### 効用

```jsonc
// package.json
{
  "packageManager": "pnpm@10.14.0"
}
```

このプロジェクトで `pnpm install` を実行すると:

1. corepack が `pnpm@10.14.0` を自動取得
2. グローバルの pnpm バージョンに依存せず、プロジェクト指定版を使う
3. チーム全員が同じ pnpm バージョンで作業可能

### 有効化

```bash
corepack enable    # Node 同梱なので追加インストール不要
```

これで `pnpm` `yarn` コマンドが corepack 経由になる。

### mise との関係

mise でも `pnpm = "10"` と書けば pnpm を管理できるが、`packageManager` フィールドの方が **チームメンバー全員に強制できる** ため、両方併用するのがベスト。

## 6. 推奨セットアップ手順(新規プロジェクト)

```bash
# 1. mise インストール(初回のみ)
curl https://mise.run | sh
echo 'eval "$(mise activate bash)"' >> ~/.bashrc

# 2. プロジェクト作成
mkdir my-project && cd my-project

# 3. .mise.toml 作成
cat > .mise.toml <<EOF
[tools]
node = "22"
pnpm = "10"
EOF

# 4. ツールインストール
mise install

# 5. 念のため互換ファイルも
echo "22" > .nvmrc

# 6. corepack 有効化
corepack enable

# 7. package.json 初期化
pnpm init
# packageManager と engines を package.json に追加
```

これで `cd my-project` するだけで Node 22 + pnpm 10 が自動で有効になる。
