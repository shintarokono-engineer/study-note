# メール送信 メモ

トランザクショナルメール送信プロバイダの選定と導入。

---

## 1. プロバイダ比較

| プロバイダ | 料金 | 無料枠 | 特徴 |
| --- | --- | --- | --- |
| **Resend** | $0 / $20〜 | 100 通/日、3,000 通/月 | DX◎、React Email 統合、即日利用可 |
| **Postmark** | $15/月〜 | 100 通(テスト) | 配送性能トップ、Transactional 特化 |
| **AWS SES** | $0.10 / 1,000 通 | Sandbox のみ | 大量送信最安、初期は Sandbox 解除申請が必要 |

選び方: **MVP は Resend**(Sandbox 申請なし、即日動く)/ 大量送信は SES / 配送性能最優先は Postmark。

本番ドメイン送信は **SPF + DKIM + DMARC** の DNS 設定が必須(未設定だとスパム判定されやすい)。プロバイダ管理画面から CNAME / TXT が発行される。

---

## 2. Resend

個人開発・小規模 SaaS 向けのトランザクショナルメール API。SDK が簡潔 + React Email 公式統合。

### 導入

```ts
import { Resend } from 'resend';
const resend = new Resend(process.env.RESEND_API_KEY);
const result = await resend.emails.send({
  from: 'Display Name <noreply@example.com>',
  to: 'user@example.com',
  subject: '件名',
  html: '<p>HTML 本文</p>',
});
if (result.error) throw new Error(result.error.message); // SDK は 200 でも error を返すケースあり
```

### ハマりどころ

- **テストモードは登録メールにしか送れない**(`from='onboarding@resend.dev'` 時、scam 防止)→ 別アドレスに送るには独自ドメイン + DNS 認証
- メール送信は **DB トランザクション外** で(コネクション占有・PG アンチパターン回避)、失敗時はベストエフォート + 再送 UI で拾う

### React Email との統合

`@react-email/render` で JSX コンポーネントを HTML に変換、Resend に渡す:

```ts
import { render } from '@react-email/render';
import { createElement } from 'react';
const html = await render(createElement(InvitationEmail, props));
// .ts ファイルでは JSX が使えないので createElement で React 要素を作る
```

注意:

- `@react-email/components` は React を peer dep として要求 → 直接 install 必要(`pnpm add react react-dom`)
- backend で JSX 使う場合は `tsconfig.json` の `"jsx": "react-jsx"` + `include: ["src/**/*.tsx"]`
